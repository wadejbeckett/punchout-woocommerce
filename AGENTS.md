# PunchOut for WooCommerce — notes for agents

Read this first, then `docs/single-login-mode.md` (the spec), `README.md` and `tests/README.md`.

## What this is
A standalone cXML PunchOut plugin for WooCommerce (namespace `POW`, source in `includes/`). A buyer's e-procurement system (for example Microsoft Dynamics 365) sends a PunchOutSetupRequest; the buyer shops in a visit and returns the basket as a PunchOutOrderMessage.

## Rules (binding)
- Standalone: no mu-plugin, no site glue file, no hook whose purpose is site glue, no `if plugin X` branch, never name another plugin or theme in code or strings. Solve inside the plugin with WordPress/WooCommerce primitives.
- The customer's WooCommerce account IS the punchout login (`partners.owner_user_id`). The plugin never creates, renames or deletes users. One WooCommerce session row per visit (`sessions.wc_session_key`, `pow_` + 28 hex). PunchOut-only exit (no checkout). Admin-only management; My Account keeps only the setup-XML download.
- Never post a PunchOut return (PunchOutOrderMessage) from a test session on a production site. Remove test items; let test sessions expire.
- This repository is public. Keep client and site names, server and hosting details, account, group and connection identities, people's names, e-mail addresses and every secret out of files, commit messages, branch names and tags. Deployment notes and records belong to whoever runs the deployment, outside this repository.
- Keep secrets out of files and logs. A connection's shared secret is read at runtime from private storage and never printed.

## Releases
- Each released version is tagged `v<version>` at its release commit and merged to `master`. Latest release: 0.4.22 (`v0.4.22`, 9 Oct 2026, hardening): the theme-drawn review relabels the posed page's title (`Addresses\ReviewTitle`, setting `review_title`, filter `punchout_review_title`; `the_title`/`single_post_title` for the posed id only, menu items put back, `woocommerce_get_breadcrumb`, document title) and draws no Punchout button (`ReviewChrome::mark_review_request()`); the front page inside an active visit redirects to the landing page (`RouteGuard::front_page_target()`, filter `punchout_visit_front_page_redirect`); a repeated Submit gets the winner's handoff again (`Sessions\HandoffReplay`, `ReturnEndpoint::replay()`, 120 s) and `delivery-review.js` sends the form once; notes lose C0 controls (`Confirmation::strip_controls()`) and a builder refusal is a 409 review message; StartPage and visit lifetimes are capped at 7 days (`Partner::MAX_TTL`); attachment downloads resolve only inside their own directory; unauthenticated audit rows have a per-IP budget of 60 requests an hour and a 4 KB setup excerpt (`Http\AnonymousAudit`); nosniff on every PunchOut response; WC tested up to 11.2. 0.4.21: the cart and visit-bar Punchout buttons (POST, no action) open the review inside the theme (`ReviewChrome::post_action()`). 0.4.20: recalculate and add-address redraw the review inside the theme (submit and back keep the dedicated route), `assets/js/delivery-review.js` applies a changed address or method at once, and DeliveryInstructions lead with "Deliver to: ..." and the delivery-estimate note (`Addresses\EstimateNote`, setting `delivery_estimate_note`, capped at 2,000 characters); 0.4.19 added that note setting. 0.4.18 (`v0.4.18`): the theme-drawn review poses as the shop's Cart page (`wp` priority 0 and `template_redirect`) so layout-driven themes draw their real header and footer, masthead left out in theme mode, filter `punchout_review_page_id`. Before it, 0.4.17 (8 Oct 2026). 0.4.14 added the optional attachment on the review page (`Orders\Attachment`: private upload directory, claimed by the Punchout Quote before the "PunchOut order received" e-mail, staff download through admin-post) and a Reply-To setting on that e-mail; 0.4.15–0.4.17 added delivery addresses from the connection account's saved addresses (`Addresses\AccountBook`, an address-book API found by function shape, never by product name; the plugin's own code map `Addresses\AccountCodes`; `wp punchout migrate-addresses`), with the company book as fallback.
- 0.4.23 is built on branch `fix/0.4.23-launch` (9 Oct 2026) and is not yet tagged, merged to `master` or released; do not describe it as installed anywhere. It changes: start links redeem only by POST (a GET or HEAD answers a small self-posting no-store page; setting `start_link_click`, off by default, needs one real click); that page sends its form once (`assets/js/start-link.js`, inlined and named by hash in its Content-Security-Policy; `X-Frame-Options: DENY`; `no-transform`), its button label is a setting (`start_link_button_label`, filter `punchout_start_link_button_label`, `StartEndpoint::button_label()`), and a repeat POST from the browser that redeemed it (current user's session token = the visit's) is sent to the landing page again (`StartEndpoint::redeemed_by_this_browser()`), every other repeat refused; the review's Submit label, items heading and total label are settings (`Addresses\ReviewLabels`, filters `punchout_review_submit_label`, `punchout_review_items_heading`, `punchout_review_total_label`); with the connection's delivery line off the review shows no estimate row, no amount beside a delivery method (`DeliveryEstimate::quote()` offers the escaped method title) and no tax sentence, and its update control says "Update delivery"; the tax sentence is a setting, off by default (`review_tax_note`); the review's own date picker is gone and new Quotes write no `_pow_preferred_delivery_date` (old Quotes keep and show theirs); no "approval" wording for buyers or in the store's own description and e-mail. No schema change.
- Address-book API contract (0.4.15): a function named `get_address_book` in any namespace, first parameter typed `WC_Customer`, second the type, returning an object with `addresses()` and `default_key()` (and `add()` for the migration). Keep it that way: detect the shape, do not name a product.
- Before a release, bump the `Version:` header, `const VERSION`, the readme `Stable tag` and the changelog, then build the package with `bin/build-zip.sh <outdir>`.

## Tests
- Unit, no Composer needed: `php tests/run-tests.php` (1331 pass at 0.4.23 on `fix/0.4.23-launch`; 1282 at 0.4.22). Also `php tests/CartBlocks/surface.php` (23), `node --test tests/CartBlocks/cart-blocks.test.js` (5), `node --test tests/Review/delivery-review.test.js` (2), `node --test tests/Start/start-link.test.js` (4), `php tests/Account/run.php` (29), `php tests/Admin/run.php` (44), and the E2E tools' own `python3 -m unittest discover -s tests/E2E -p 'test_*.py'` (75).
- Native suites (opt-in) need a disposable WordPress + WooCommerce + MariaDB site with this plugin linked in; see `tests/README.md`. Example: `POW_NATIVE_TESTS=disposable POW_NATIVE_SCRIPT=$PWD/tests/Integration/TwoBuyerNative.php wp --user=1 eval 'require getenv("POW_NATIVE_SCRIPT");'` (the same for VisitLockdownNative, SessionSafetyNative, AddressSchemaNative, AdminActionsNative and DeliveryStoreNative). RegistrationLifecycleNative runs via `eval-file`. ConcurrencyNative also needs `POW_NATIVE_CONCURRENCY_MODE=suite`, `POW_NATIVE_WP_CLI`, `POW_NATIVE_WP_PATH`, `POW_NATIVE_WP_USER` and `POW_NATIVE_FIXTURE_ROOT`.
- Real browser (opt-in, same fixture, Python Playwright and a local Chromium, never downloaded): `python3 tests/E2E/browser.py --wp-path <site> --wp-cli <wp-cli.phar> --chromium <chrome> --link-plugin "$PWD"` opens a start link in headless Chromium (auto and double click), checks the landing page is inside the visit, and reads the review with freight off; runbook in `tests/README.md`, "Real-browser run".
- End-to-end over real HTTP (opt-in, disposable local fixture): `python3 tests/E2E/driver.py --wp-path <site> --wp-cli <wp-cli.phar> --link-plugin "$PWD"` sends a Dynamics-shaped setup request, redeems, fills the cart, returns it and validates the cXML; its own unit tests are `python3 -m unittest discover -s tests/E2E -p 'test_*.py'`. Runbook: `tests/README.md`, "End-to-end HTTP driver".
