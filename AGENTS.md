# PunchOut for WooCommerce — notes for agents

Read this first, then `docs/single-login-mode.md` (the spec, with its 0.5.0 note), `README.md` and `tests/README.md`.

## What this is
A standalone cXML PunchOut plugin for WooCommerce (namespace `POW`, source in `includes/`). A buyer's e-procurement system (for example Microsoft Dynamics 365) sends a PunchOutSetupRequest; the buyer shops in a visit and, since 0.5.0, leaves through WooCommerce's classic checkout with the PunchOut payment method, whose Submit sends the placed order back as a PunchOutOrderMessage.

## Rules (binding)
- Standalone: no mu-plugin, no site glue file, no hook whose purpose is site glue, no `if plugin X` branch, never name another plugin or theme in code or strings. Solve inside the plugin with WordPress/WooCommerce primitives.
- The customer's WooCommerce account IS the punchout login (`partners.owner_user_id`). The plugin never creates, renames or deletes users. One WooCommerce session row per visit (`sessions.wc_session_key`, `pow_` + 28 hex). Admin-only management; My Account keeps only the setup-XML download.
- The way out of a visit is the shop's classic checkout with the `punchout` payment method, the only one offered there, and Cancel and return (the empty message). Nothing is paid in a visit: another method, the Store API checkout, order-pay and order-received are refused in a visit, PunchOut is refused outside one, and a PunchOut order is never payable. During a visit checkout saves nothing to the bound account. (Ruling of 9 October 2026, 13:05: this replaces the 0.4.x rule that a visit's one way out was the plugin's own review page and that checkout was refused in a visit; that page is retired.)
- Only PunchOut **button labels** are settings (the place-order label on the payment method, Checkout button label, Cancel button label, the leave question's two buttons, the state page's button, the login link's button). Titles, body text and the leave question ship as neutral, translatable defaults that a layout overrides as shortcode attributes. The plugin shows a buyer no estimate, price, delivery or tax wording of its own, and never the word "approval" (the purchasing system approves, not the shop).
- Never post a PunchOut return (PunchOutOrderMessage) from a test session on a production site. Remove test items; let test sessions expire.
- This repository is public. Keep client and site names, server and hosting details, account, group and connection identities, people's names, e-mail addresses and every secret out of files, commit messages, branch names and tags. Deployment notes and records belong to whoever runs the deployment, outside this repository.
- Keep secrets out of files and logs. A connection's shared secret is read at runtime from private storage and never printed.
- Classic checkout only: the plugin declares itself incompatible with the cart and checkout blocks (`cart_checkout_blocks`, false). Do not add block-checkout support without a decision.

## Releases
- Each released version is tagged `v<version>` at its release commit and merged to `master`.
- **0.5.0** (branch `feature/0.5.0-int`, October 2026; this is the release candidate): WooCommerce's classic checkout is the visit's way out. `Checkout\PaymentMethod` and `Checkout\Gateway` (the `punchout` method, only while a live visit owns the request, then the only one, filtered in last; a build failure leaves the order pending); `Checkout\OrderMessage` (lines, line description modes, ShipTo from the order's shipping address, DeliveryInstructions = note | order details, freight with the estimate sentence only while `emit_delivery_line` and the shipping total is more than zero: a free-shipping order sends no line and no sentence, ruling of 11 October; `estimate_sentence()`, filter `punchout_delivery_estimate_note`); `Checkout\Handoff` (`GET /punchout/handoff`, served once, keyed to the order key and the visit's login, claimed by its delete; `/punchout/sent`); `Checkout\Lifecycle` (zero-total carts need payment, never auto-cancelled, the loser of a race bins its order); `Checkout\LateSubmit` (a Submit after the return goes to the Sent state before WooCommerce's nonce check); `Checkout\Provenance` (stamped as checkout creates the order); `Checkout\VisitAccount` (`woocommerce_checkout_update_customer_data` false first and last; billing from the account's saved profile; the account fence: inside a live visit every add, update and delete of the visit's account's user meta is refused through `add|update|delete_user_metadata`, early and last, except `session_tokens`, `wc_last_active`, `last_update` and `_woocommerce_persistent_cart_*`, each refused key audited once as `visit_account_write_refused`). `RouteGuard` admits classic checkout in a visit with the PunchOut method only, refuses order-received for a visit, and inside a visit answers the Store API's `order/{id}` and `checkout/{id}` reads only for the visit's own order. The handoff and the Not sent page send `X-Frame-Options: DENY` and a Content-Security-Policy naming their own inline script and styles by hash with `form-action` the receiver's origin; a handoff GET with neither login cookie nor sent marker goes to Session ended before any order is read, and the kept page is claimed only once order and visit match. Checkout also refuses, while the connection sends ShipTo, a posted delivery address with a street that cXML cannot carry. "Order details sent" refuses keys beginning with `_pow_`. The hourly job bins (no status change) pending orders carrying `_pow_session_id` whose visit is over and that are older than the handoff TTL (`QuoteOrder::trash_stale_pending()`). Schema 10 adds only `line_description` and `order_details` (0.4.23 never names them: a rollback needs no data change); the connection form gains Send delivery cost, Send ShipTo, Line description and Order details sent (`Partners\OrderDetails`; filters `punchout_line_description_limit`, `punchout_order_details_sent`). ## Tests
- Unit, no Composer needed: `php tests/run-tests.php` (1165 pass at 0.5.0). Also `php tests/CartBlocks/surface.php` (32), `node --test tests/CartBlocks/cart-blocks.test.js` (5), `node --test tests/Start/start-link.test.js` (4), `node --test tests/Leave/leave-confirmation.test.js` (4), `php tests/Account/run.php` (29), `php tests/Admin/run.php` (50), and the E2E tools' own `python3 -m unittest discover -s tests/E2E -p 'test_*.py'` (134).
- Native suites (opt-in) need a disposable WordPress + WooCommerce + MariaDB site with this plugin linked in; see `tests/README.md`. Example: `POW_NATIVE_TESTS=disposable POW_NATIVE_SCRIPT=$PWD/tests/Integration/TwoBuyerNative.php wp --user=1 eval 'require getenv("POW_NATIVE_SCRIPT");'` (the same for VisitLockdownNative, SessionSafetyNative, AddressSchemaNative, AdminActionsNative, CompanyBookNative, NativeImportNative and VariationLineNative). RegistrationLifecycleNative runs via `eval-file`. ConcurrencyNative also needs `POW_NATIVE_CONCURRENCY_MODE=suite`, `POW_NATIVE_WP_CLI`, `POW_NATIVE_WP_PATH`, `POW_NATIVE_WP_USER` and `POW_NATIVE_FIXTURE_ROOT`.
- Real browser (opt-in, same fixture, Python Playwright and a local Chromium, never downloaded): `python3 tests/E2E/browser.py --wp-path <site> --wp-cli <wp-cli.phar> --chromium <chrome> --link-plugin "$PWD"` opens a start link in headless Chromium (auto and double click), checks the landing page is inside the visit, drives the classic checkout with WooCommerce's own script (cart "Review" → only PunchOut, "Submit" → a saved shipping entry → the Sent state, one cXML at the receiver), then the state page and the leave question; runbook in `tests/README.md`, "Real-browser run".
- End-to-end over real HTTP (opt-in, disposable local fixture): `python3 tests/E2E/driver.py --wp-path <site> --wp-cli <wp-cli.phar> --link-plugin "$PWD"` sends a Dynamics-shaped setup request, redeems, fills the cart, leaves through the classic checkout, captures the handoff's cXML and validates it, then runs the second leg (the race, a zero total, a SKU-less line, a pending order, the refusals, the states); its own unit tests are `python3 -m unittest discover -s tests/E2E -p 'test_*.py'`. `--path review` is refused on a build with the PunchOut payment method. Runbook: `tests/README.md`, "End-to-end HTTP driver".
